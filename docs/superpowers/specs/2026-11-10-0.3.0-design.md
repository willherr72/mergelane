# MergeLane 0.3.0

The user requested clearer saved/add connection flows and chose to include category explanations and more control over automatic closure in the same release, with good testing.

## Agreed behavior and implementation choices

- Settings separates Saved connections from an explicit Add connection form. Adding starts blank; buttons labeled as detected from open PR tabs suggest unsaved owners. Replace token locks the existing owner. Adding an already saved owner directs the user to Replace token. Existing default tokens remain replaceable and removable.
- Saved connections show Not checked yet, Account verified (repository access untested), Access verified with check time, or Needs attention. Check and Reconnect operate on the specified connection. A rejected replacement does not downgrade the saved token's health.
- The popup lists tracked PRs with the selected category and a plain-language explanation computed from the same rule predicates as classification. Any/all, negation, fallback, disabled rules, changed state, and errors must not produce misleading explanations. Category explanations live beside the PR; Settings still edits rules.
- Recent closures stores the latest 30 unique PRs locally, with canonical URL, title, closure reason and time. Only successful automatic tab closures are recorded. Reopen and keep open writes a persistent per-PR cleanup exemption before opening or focusing the PR. Multiple tabs for a PR share that exemption. No exemption is silently evicted.
- Keep open is also available for tracked PRs. The popup lists protected PRs even after their tabs close, with Resume cleanup to explicitly remove protection. Protection affects cleanup only; grouping continues. Recent history can be cleared without removing protections.
- Cleanup protections are operational state separate from category drafts. Commands invalidate in-flight reconciliation; every removal still checks current state and live URL. Closure records survive canceled runs after actual removals. Reopen accepts only recorded GitHub PRs, never arbitrary URLs. Settings, tokens and current pause state migrate unchanged.
- The popup may scroll; Chrome group titles remain short. Continue the existing Material styling. No additional permissions, hosted service, or telemetry.

## Scope

Approaches considered: explanations in Settings alone would not identify individual PR decisions; longer native group titles would be noisy. The selected popup approach keeps the reason beside the PR and provides cleanup recovery in the same place. User authorization covers both capabilities and the connection clarification. No notifications, shared settings export, or repository exclusions in this release.

## Verification

Unit tests cover explanation correctness, protected merged/old-closed PRs, normal cleanup unaffected, recent history deduplication/cap, protected state independent of stale drafts, and per-owner health. Native Chromium tests cover add vs replace, blank owner/suggestions, assisted import, popup reasons, reopen protection through worker/browser restart, resume cleanup, and permission/error regressions. Repeat existing grouping/closure and import suites. Review before publishing version 0.3.0.
